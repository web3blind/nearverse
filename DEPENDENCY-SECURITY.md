# Разбор безопасности зависимостей NearVerse

## Область проверки

Проверены закреплённые manifest/lockfile, `npm audit` с dev-зависимостями и без них, опубликованные версии и зависимости пакетов, исходники SDK и используемые NEAR-пути приложения. Это не пентест и не доказательство отсутствия уязвимостей. SDK core/standalone остаётся 7.29.0; собственных криптографических, обменных или wallet-адаптеров не добавлено.

## Применённые изменения

- Vite 7.2.2 → 7.3.7. Совместим с Node 22.22.0 и закреплёнными React plugin/Vitest/polyfills. Убраны GHSA-v2wj-q39q-566r, GHSA-p9ff-h696-f583, GHSA-587h-7wmj-h5pm. Это уязвимости dev-сервера, не доказанные ошибки compiled Express preview.
- Только внутри `@hot-labs/omni-sdk@2.24.3`: `@solana/web3.js` 1.68.0 → 1.68.2, официальная исправленная patch-ветка GHSA-8m45-2rjm-j347. Другие Solana версии не заменены глобально.
- Только для `ethers@6.15.0`: `ws` 8.17.1 → 8.21.0. Убраны high GHSA-96hv-2xvq-fx4p и соответствующее moderate-предупреждение. Переход ethers на другую версию с изменениями поведения не делался; другие ws@7 потребители не затронуты.

До установки manifest/lockfile сохранены в приватном scratch. Сравнение lockfile подтвердило ровно три смены версий существовавших путей и отсутствие удалённых путей. npm также добавил 107 lockfile-путей при переразмещении/разрешении зависимостей; это не утверждение о 107 новых реально загруженных runtime-пакетах. Обычный `npm install --ignore-scripts --prefer-offline` завершился за 19 секунд, без пересоздания native SQLite. Явный WalletConnect SignClient 2.26.0 сохранён: его удаление ранее ломало standalone в браузере.

## Измеренный результат

Счётчик npm включает пакеты, которым severity передана от зависимостей. Он не равен числу независимых ошибок NearVerse.

- Всё дерево: 75 → 72 записи; high 42 → 40. Независимые high-advisories по уникальному URL: 17 → 12. Убрано пять, новых high-advisories не появилось.
- Production (`--omit=dev`): 69 → 67 записей; high 41 → 40, moderate 9 → 8, low 19, critical 0. Независимые high-advisories: 14 → 12.
- Свежие полные отчёты: `data/audit-full.json`, `data/audit-production.json`, не Git. Воспроизведение: `npm audit --json` и `npm audit --omit=dev --json`; ненулевой exit ожидается, пока остаются предупреждения.

## Что осталось и почему это не заменено принудительно

- `zod` 3.25.76 и вложенные 3.22.4: GHSA-mrhx-c7xc-m3w5, исправление в 4.6.6. SDK требует `^3.25.51`, совместимого исправленного v3 нет. Zod действительно используется для ответов RPC/балансов на поддерживаемом NEAR/Intents пути; огромные некорректные массивы могут вызвать накопление ошибок и отказ интерфейса. Нужен контроль над полученным ответом; произвольный публичный HTTP-эксплойт backend этим не доказан. Нельзя объявлять эту библиотеку недостижимой или глобально заменить v3 на v4 без миграции контрактов.
- `bigint-buffer` 1.1.5: GHSA-3gc7-fjrx-p6mg. Исправленного опубликованного релиза нет. Браузер выбирает pure-JS реализацию вместо уязвимого native `toBigIntLE`; серверные auth/arrival пути не вызывают найденную Solana-конвертацию. Нативный эксплойт поддерживаемого пути не воспроизведён. Не пересобирать этот addon ради устранения предупреждения о JS fallback.
- `protobufjs` 6.11.6 через ICS23/Cosmos: пять high-advisories. Потребитель использует `protobufjs/minimal` и сгенерированные codecs, а не произвольную динамическую схему. На поддерживаемом NEAR-пути обработка ICS23 proof не найдена. Для новых Cosmos-путей нужен отдельный разбор рекурсивного декодирования. Исправленная ветка 7.6.6 — major по отношению к `^6.8.8`; совместимость runtime/Long не доказана.
- `toml` 3.0.0: пять high-advisories, исправленная ветка 5.0.1. Найден в Anchor workspace/config и Stellar-зависимостях; пользовательский TOML на NEAR-пути приложения не разбирается. Все найденные потребители требуют v3. Замена через две major-версии не принята без проверки контрактов. 4.2.0 не устраняет все текущие предупреждения.

Официальный Aurora core/standalone latest при проверке остаётся 7.29.0. HOT 2.25.5 продолжает закреплять исходные уязвимые версии Solana/ethers; простое обновление HOT не устраняет их. `npm audit fix --force`, правки `node_modules` и подстановка непроверенных forks не применялись.

## Существенное ограничение оценки

Фильтр активов не отключает все остальные кошельки standalone. При импорте инициализируются EVM/Solana AppKit и Stellar hooks. «Код загружен» и «уязвимая функция обработала контролируемые данные» — разные факты. Поэтому нельзя ни объявить все предупреждения эксплуатируемыми, ни списать их одной фразой «приложение NEAR-only». В серверных auth/arrival-путях вызовов перечисленных high-функций не найдено; это не универсальная гарантия безопасности сервера.

Перед реальными средствами нужно отдельно рассмотреть оставшийся риск SDK и согласовать сеть, актив, сумму/лимит и маршрут. Нулевой аудит и полная security-приёмка не заявляются.
